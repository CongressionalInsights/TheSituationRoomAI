## Outcome and limits

Reduce validation feedback time and runner work while retaining the required
`preflight` context, dependency/syntax validation, regression coverage, and release
guards. This task authorizes source changes and local verification. It does not
authorize production dispatch, publishing this branch, changing protection,
credentials, billing, monitoring cadence, or deployment behavior.

The existing Node runner and repository fixtures are sufficient. No new runner
provider, dependency, test-selection service, result cache, or shard fleet is
needed. Stop when the retained contracts and full offline inventory pass, the
patch is reviewed, and measured results and their limits are recorded.

offline suite on every PR and push rather than introduce an unproved selector.

## Historical baseline

Read-only GitHub inspection at approximately 22:30–22:40 Eastern on November 16
found a public repository with nine checked-in workflows. `main` protection
requires the GitHub Actions context `preflight`, strict against the base, and
enforces administrators. No rulesets were returned. This configuration is not
changed by the patch.

The frozen sample is the latest 100 runs returned at audit start, from
`2026-11-15T17:05:16Z` through `2026-11-17T03:10:46Z`. It includes failures,
cancellations, releases, scheduled work and native Pages publication. Job/step
metadata was collected for all 94 runs owned by checked-in workflows or native
Pages. Six dynamic Dependabot runs were excluded from job collection, not
silently counted as zero. See [the normalized snapshot](baseline-2026-11-16.json).
This short activity sample is not a monthly projection.

| Work | Sample | Median job seconds | Sum job seconds |
| --- | ---: | ---: | ---: |
| PR MCP preflight | 9 | 58 | 515 |
| Push MCP preflight | 7 | 53 | 378 |
| Manual MCP preflight | 2 | 54.5 | 109 |
| Scheduled Pages source build/publication | 35 | 112 | 4,400 |
| Native Pages build | 35 | 8 | 322 |
| Native Pages deploy | 35 | 10 | 369 |
| Native Pages report | 35 | 4 | 173 |

PR feedback from workflow creation to preflight completion: median 60 seconds;
creation-to-job-start: median 2 seconds. Job duration and queue-inclusive feedback
are different clocks. Summed jobs measure compute occupancy, not workflow latency.
Skipped deploy jobs are excluded from runner time. These are API timestamp
measurements at second resolution, not invoice data or CPU utilization.

Across the 18 MCP preflights, dependency installation had a median of 2 seconds.
The last Feed/BLS fixture step had a median of 27.5 seconds; CISA fixtures took
11 seconds. Pages' static data acquisition took a median of 93 seconds across
36 source-build runs. Source acquisition, publication, and deployments are
separate from PR validation and remain intact.

The repository uses standard `ubuntu-latest` runners and is public. GitHub lists
standard hosted runners in public repositories as
[free compute](https://docs.github.com/en/billing/concepts/product-billing/github-actions).
Thus runner seconds and local CPU seconds are useful efficiency measures; a
95% cash saving would be an unsupported claim. Cloud Build, provider requests,
model calls, storage and paid runner costs were not measured here.

## Ranked changes

1. **Close test-owned HTTP connections after assertions.** Fixture shutdown waits
   consume observable wall time. Reuse the existing `closeAllConnections()`
   teardown pattern. Keep payload sizes, deadlines, isolation and assertions.
2. **Discover the entire offline inventory and remove cross-spec imports.**
   `npm test` names 12 entry files; transitive spec imports hide additional
   coverage, while six Node specs and the adapter suite are absent. Running all
   files naively repeats imported suites. Move the shared native-build fixture
   into a data/helper module, and execute each spec as its own isolated file.
3. **Use that full inventory in the existing required job.** Retain its ID,
   triggers, source checks, pinned Node, dependency install and release binding.
   Install State Connector's lockfile too, so clean checkouts can execute its
   adapter contracts. Cancel superseded PR preflights only; isolate push and
   manual preflights and retain release serialization without cancellation.

Deferred: dependency caching (only ~2 seconds available before cache overhead),
runner replacement, sharding and learned/affected-test selection (no demonstrated
benefit at this scale). Pages consumes most sampled time, but reducing freshness,
changing acquisition policy or eliding publication needs separate product
evidence. Preserve the hourly schedule and daily monitor baseline/artifacts.

## Reproduction and acceptance

Historical data was read with `gh api` using:

```sh
gh api 'repos/CongressionalInsights/TheSituationRoomAI/actions/runs?per_page=100'
gh api 'repos/CongressionalInsights/TheSituationRoomAI/actions/runs/RUN_ID/attempts/ATTEMPT/jobs?per_page=100'
gh api repos/CongressionalInsights/TheSituationRoomAI/branches/main/protection
gh api repos/CongressionalInsights/TheSituationRoomAI/rulesets
```

Pin `.nvmrc` (Node 24; locally 24.22.1), then install both execution roots:

```sh
npm ci --prefix gcp/mcp-proxy
npm ci --prefix gcp/state-connector
npm test
```

An initial run with only MCP installed failed before the State Connector tests
loaded (`fast-xml-parser` missing). Installing its own lockfile made that focused
suite pass. That bootstrap failure is retained as a prerequisite finding, not
counted as a product regression or a green baseline.

Local benchmarks run sequentially on the same source, host and Node version.
Use Python `time.monotonic()` around `subprocess.run()` for wall time and the
delta of `resource.getrusage(resource.RUSAGE_CHILDREN)` for child user/system CPU.
Record commands, exit codes and test counts alongside timing. Compare identical
inventories separately from the old narrower preflight. An early overlapping
exploratory run is excluded from paired performance claims.

Final measurements and review evidence are appended after implementation.
