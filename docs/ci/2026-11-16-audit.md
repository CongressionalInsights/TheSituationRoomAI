## Outcome and limits

Reduce validation feedback time and runner work while retaining the required
`preflight` context, dependency/syntax validation, regression coverage, and release
guards. This task authorizes source changes and local verification. It does not
authorize production dispatch, publishing this branch, changing protection,
credentials, billing, monitoring cadence, or deployment behavior.

The existing Node runner and repository fixtures are sufficient. No new runner
provider, dependency, test-selection service, result cache, or shard fleet is
needed. Stop when the retained contracts and full offline inventory pass, the
patch is reviewed, and measured results and their limits are recorded.

standard hosted runners in public repositories as

Thus runner seconds and local CPU seconds are useful efficiency measures; a
95% cash saving would be an unsupported claim. Cloud Build, provider requests,
model calls, storage and paid runner costs were not measured here.

## Ranked changes

1. **Discover the entire offline inventory and remove cross-spec imports.**
   `npm test` names 12 entry files; transitive spec imports hide additional
   coverage, while six Node specs and the adapter suite are absent. Running all
   files naively repeats imported suites. Move the shared native-build fixture
   into a data/helper module, and execute each spec as its own isolated file.
2. **Use that full inventory in the existing required job.** Retain its ID,
   triggers, source checks, pinned Node, dependency install and release binding.
   Install State Connector's lockfile too, so clean checkouts can execute its
   adapter contracts. Cancel superseded PR preflights only; isolate push and
   manual preflights and retain release serialization without cancellation.
3. **Stop repeating retry backoffs in parser/error fixture tests.** Use the
   client's existing `retry: false` option in those tests. Retain retry behavior
   under one explicit virtual-time contract covering transport, invalid response,
   response size and RPC errors: attempts occur after 500 and 1,200 milliseconds,
   with exactly three attempts. Payload sizes, response assertions, isolation,
   production retry behavior and production code remain intact.

Deferred: dependency caching (only ~2 seconds available before cache overhead),
runner replacement, sharding and learned/affected-test selection (no demonstrated
benefit at this scale). Pages consumes most sampled time, but reducing freshness,
changing acquisition policy or eliding publication needs separate product
evidence. Preserve the hourly schedule and daily monitor baseline/artifacts.

An initial run with only MCP installed failed before the State Connector tests

Use Python `time.monotonic()` around `subprocess.run()` for wall time and the
delta of `resource.getrusage(resource.RUSAGE_CHILDREN)` for child user/system CPU.
Record commands, exit codes and test counts alongside timing. Compare identical
inventories separately from the old narrower preflight. An early overlapping
exploratory run is excluded from paired performance claims.

## Measured candidate

| Local lane | Executions | Wall seconds | Child CPU seconds |
| --- | ---: | ---: | ---: |
| Baseline: all 30 existing offline specs, with transitive duplication | 1,004 | 66.32 | 87.38 |
| Candidate: complete discovered inventory, including new checks | 780 | 38.83 | 57.52 |
| Candidate repeat after fresh dependency installs: tests only | 780 | 49.03 | included in 57.90 below |
| Candidate complete local preflight: sync, installs, syntax, tests | 780 | 51.30 | 57.90 |
| Baseline: nine sequential CI test commands, narrower coverage | see recorded commands | 52.25 | 41.64 |

The first full-inventory comparison is **41.5% less wall time and 34.2% less child
CPU** in this local pair. The repeat showed substantial wall-time variation:
tests took 49.03 seconds, still 26.1% below the 66.32-second baseline. Report the
observed **38.8–49.0-second range**, not a guaranteed 41.5% improvement. CPU for
the entire repeated preflight remained 33.7% below the baseline full inventory.
These are two candidate samples and one baseline, not a statistical guarantee.
The candidate includes feed-registry parity validation
and eight new checks. All 772 distinct baseline case names appear among the
780 passing candidate cases: no baseline case name was lost. Removing duplicate
executions accounts for the lower total. Case-name comparison supports the
source review; it is not a substitute for assertion review. Full commands,
timings and retained names are in [the measurement receipt](local-measurements-2026-11-16.json).

The old CI subset uses less CPU than the expanded candidate, so there is no
claim that expanded coverage is computationally free. It executes fewer
contracts. Fixed-runner occupancy follows elapsed job time rather than summed
child CPU; using more of a runner while returning a full answer sooner is the
intended tradeoff. The local candidate is 13.4 seconds faster than the old
test-command sequence in the first sample, but the complete repeated local
preflight took 51.30 seconds. This does not establish a hosted end-to-end saving.

No affected-test narrowing, test result reuse or in-process cross-file sharing
was enabled. The required check still runs for every PR/push. PR concurrency
was validated in source, not exercised against live queued runs. Pages, monitor,
cloud release commands, schedules, credentials and branch protection are
unchanged; the MCP deploy job compares byte-for-byte equal to the baseline.

Validation: full `npm test` (780 passing, zero failed/skipped), feed parity,
Node syntax checks, failure/empty-inventory CLI fixtures and workflow validation
with `actionlint -shellcheck=`. Full actionlint reports one existing ShellCheck
SC2016 advisory in the unchanged release script; its baseline was retained.
Browser tests and live monitors are separate lanes and were not used as offline
CI timing evidence. No hosted candidate run, deployment or billing experiment
was performed. After an authorized PR run, compare job duration, queue-inclusive
feedback and summed runner seconds against the same baseline; report cache/setup
and workload differences rather than applying the local percentage to hosted CI.

## Rejected experiment

The first hypothesis was fixture connection shutdown. Adding explicit connection
closure passed the focused monitor/CISA run but did not materially reduce its
60.6-second duration. Those edits were removed. Source inspection then identified
the real 500/1,200-millisecond retry backoffs repeated by failure fixtures. The
existing `retry: false` interface allowed a test-only change, with stronger
independent virtual-time proof for the retry contract. No retry policy or monitor
runtime implementation was changed.
