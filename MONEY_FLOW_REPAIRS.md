### LDA limit investigation and complete query traversal

The 12-attempt/3-page caps were introduced by this repair's initial commit `9533caaf261bdda5e05c3906e7aae2074f194e50`. They were implementation choices, not provider requirements. Deployed baseline `c51867c` instead fetched first pages and used a 45-second per-request timeout; it had no such request-count cap. The current official [LDA terms](https://lda.gov/api/tos/) publish **15 requests/minute anonymously and 120/minute with a registered API key**; [API documentation](https://lda.gov/api/redoc/v1/) specifies a maximum of **25 records per page**. These are rate/page-size constraints, not total acquisition limits. This adapter uses anonymous access; no LDA credential was added or requested.

Five Strategic Education aliases across two years require 60 initial searches (three filing filters and three LD-203 filters per alias-year). At 4.1-second spacing, the old shared 45-second slice allowed at most 11 starts even with zero response latency, so all 30 LD-203 searches could be unattempted. Three pages also arbitrarily capped a search at 75 envelopes. Removing the total caps alone does not make 60 requests fit a 60-second caller: one-page-per-search coverage takes about four minutes at the anonymous rate, and longer searches take longer.

`money.flows` now accepts `mode: "lda_pages"` and optional `cursor`. The same parameters work on Feed/local `/api/money-flows` (use `q` for `query`). Start with a fixed query/window; then persist each response's rows and use the exact `ldaTraversal.next` arguments for the following call until `ldaTraversal.complete` is true and `next` is null:

```json
{"query":"Strategic Education","start":"2025-01-01","end":"2026-11-03","mode":"lda_pages"}
```

Each call fetches one provider page and returns **all matching normalized rows**, including every relevant LD-203 child. `limit` is intentionally ignored in page mode; it cannot silently discard rows before advancing. All expanded aliases are searched, including beyond the aggregate's eight-variant sample limit. Filings and LD-203 searches interleave. A cursor carries a version, frozen-query fingerprint, search/page position, previous-page identity fingerprint and earliest next request time; it contains no provider URL, credential or payload. The server reconstructs and validates requests. Changing dates, aliases or matching options rejects the cursor before fetching. A failed page stays pending for later recovery under the existing bounded-retry policy; do not blindly loop on an error. Repeated pages and query-changing next links remain errors, never completion.

Requests are spaced 4.1 seconds apart within the sample and across the returned continuation chain. HTTP 429 `Retry-After` is carried forward; an early continuation whose wait exceeds the response slice makes no request and keeps the same page pending. This is cooperative per-traversal pacing, not a global cross-instance quota controller. Concurrent unrelated callers can still trigger provider throttling. No controller, schedule, signing secret or checkpoint store was added.

The initial repair also imposed an unsupported ten-calendar-year input gate. That gate is removed: ordered valid date ranges are accepted without clipping older years. LDA still sends one `filing_year` per provider request, so a longer caller window does not create a multi-year provider request. Page mode computes its current year/alias/filter directly from the existing version-1 cursor, without enumerating the historical cross-product or changing cursor order. Aggregate LDA/FEC search plans are also generated only as attempted; their existing response/request bounds and financial meaning remain intact. Historical provider errors remain errors with an unfinished page, not invented zero activity or silently excluded years.

An aggregate response exposes `ldaTraversal.next` with `startsFromBeginning:true`. It explicitly starts a separate full traversal from page one: the ranked aggregate may already have hidden acquired rows, so resuming after them would lose data. Deduplicate by `(source, sourceId)` across pages, OR filters, repeated failed pages, and any prior sample. Advance the existing Fusion checkpoint only after successful write/readback. A lost response can be replayed with the same input cursor. `coverage.status: "lda_page"` identifies this new mode; completion applies to the traversed query plan, not all entity activity. Source counts and monetary subtotals remain per response; other sources are marked `not_requested` and are not fetched in this mode.

LDA uses mutable page-number pagination, not a snapshot/keyset API. Late filings or edits can move pages while a traversal runs; cursor completion is not proof of original point-in-time knowledge. For question-relevant historical gaps, retain the frozen window and existing bounded-overlap/identity-dedup process, record acquisition time, and retain uncertainty when the provider cannot establish the original view. The new path enables full query traversal; it does not recover lost historical observations or reconcile amendments.

## Caller contract and presentation

`schemaVersion: 2` deliberately changes financial interpretation:

- `amount`, summary amounts and top-entity amounts are nullable. An actual zero remains zero. Buckets expose known/unknown amount counts; missing amounts never become zero. SAM has no monetary subtotal.
- `coverage.status` is `discovery_sample` in default aggregate mode, with `complete:false`, matched/returned counts and output/query-variant truncation. Summaries have `basis: returned_rows_only`. Exhausted individual queries do not establish global entity coverage.
- Each source reports coverage status, reasons, searches/pages/requests and cached searches. `count` is acquired rows before deduplication/matching; `returnedCount` is the displayed normalized rows. LD-203 acquired rows are filing envelopes; returned rows are children.
- LDA selection is by whole filing year; contribution dates are filtered where known. Unknown dates are preserved. SAM is a current registration snapshot. Neither is silently claimed to meet the exact receipt/transaction date window.
- Existing MCP input names and retrieval annotations are unchanged; optional `mode`/`cursor` inputs add LDA traversal. The metadata test fingerprint covers the reviewed description and input additions; the pinned metadata-only deployment exception is unchanged.
- Feed/local paths now share MCP alias matching and a maximum of 120 results (Feed Proxy previously allowed 200). They accept the same optional matching controls. Callers must consume truncation/coverage metadata, not assume the requested count was retrieved.
- The UI shows sampling and unavailable sources even for zero returned rows, labels transaction obligations, displays `$0` and negative amounts correctly, separates unknown values, and displays SAM registration counts instead of dollars. Its request timeout is 60 seconds, above the bounded acquisition deadline. Frontend artifacts were rebuilt.

## LD-203 child retention follow-up

Based on merged source `965582e66e1a39dd00198670ed43f625079946f8`, the retention-only follow-up keeps repeated LD-203 parent payloads already fetched by the existing acquisition. Parent identity still controls pagination diagnostics and the repeated-page stop; no endpoint, filter, query binding, pacing, deadline, request/page bound or retry is changed. Normalization deduplicates children by filing and native child identity, retaining the first observed values. Different filing identities, including amendments, remain separate. Sample ranking/limit still applies after normalization; page mode retains all matching normalized children.

Missing native child IDs remain `childId:null`. Their explicitly labeled `childIdentityBasis:content_occurrence_fallback` uses a canonical content fingerprint and occurrence within each parent payload. This keeps distinct content and multiplicity within a payload, and prevents repeated identical views from multiplying the same observations. It cannot determine whether identical ID-less records in separate views represent different real contributions, or reconcile changed versions without native lineage. Native child source IDs are unchanged; missing-ID source IDs change from positional suffixes to labeled content/occurrence suffixes. Consumers combining old and new acquisitions must not assume those fallback IDs are interchangeable or treat them as native identities. The candidate verifier retains the distinction while accepting legacy positional receipts.

Inert regressions cover OR filters, duplicate parents within one page, an already-fetched overlap page, duplicate/conflicting native child values, null/missing/zero/negative amounts, ID-less multiplicity, separate amendment filings and page-mode retention. The pagination stop remains explicit even when the stopped page supplied new children. These fixtures prove an accepted-shape baseline loss; the retained live parent-only hashes do not prove different child payloads on the actual repeated provider page. No source recovery or comprehensive coverage is claimed.

At the LD-203-only review stage, FEC remained design-only. Its bounded sample can retain successfully parsed rows while losing the exact native continuation state on page-budget/deadline exit. A future stateless continuation would need frozen query/entity/cycle/order binding, separate unfinished-query cursors, failed-page replay state, pacing/Retry-After, validation and caller-side persistence/deduplication. It could resume within each call's unchanged bounds, but adds a public contract and mutable-provider consistency risks; sanitized diagnostics must not export raw cursors, URLs or credentials. Merely lengthening the timeout would not preserve those cursors or solve the page cap, and can conflict with caller timeouts and consume more quota. Neither continuation nor longer budgets/timeouts/retries was implemented in that LD-203-only repair.
